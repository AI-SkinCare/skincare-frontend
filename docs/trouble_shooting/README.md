# Trouble Shooting 작성 가이드

개발 중 생긴 문제(빌드 실패, 런타임 크래시, API 연동 오류, 시뮬레이터/서명 문제 등)와 해결 과정을 기록하는 곳.
같은 문제를 다시 겪지 않고, 팀원이 검색해서 바로 해결할 수 있게 하는 것이 목적.

## 언제 적나

- 에러 메시지가 나왔고 해결하는 데 **5분 이상** 걸린 경우
- 원인이 코드가 아니라 환경/설정(Xcode, 서명, SPM, 시뮬레이터, 백엔드 연동)인 경우
- 해결은 못 했지만 우회한 경우 → 상태 `미해결` 또는 `우회`로 기록

## 폴더 구조

```
docs/trouble_shooting/
├── README.md          # 이 문서 (작성 규칙)
├── TEMPLATE.md        # 새 문서 만들 때 복사할 양식
├── INDEX.md           # 전체 목록 (새 문서 추가 시 한 줄 추가)
├── build/             # Xcode 빌드, 컴파일, SPM 의존성, 서명/프로비저닝
├── runtime/           # 크래시, 메모리, 동시성(async/await), 성능
├── ui/                # SwiftUI 레이아웃, 내비게이션, 디자인 시스템 적용 문제
├── network/           # 백엔드 API 연동, 인증, 폴링, 디코딩
├── camera/            # 카메라·영상 촬영, 권한, AVFoundation
└── env/               # 개발 환경, 시뮬레이터, 툴링, Claude Code 설정
```

카테고리가 애매하면 가장 먼저 증상이 나타난 곳 기준으로 넣는다. 새 카테고리가 필요하면 폴더를 만들고 위 트리와 `CLAUDE.md`를 갱신한다.

## 파일 이름

```
YYYY-MM-DD_짧은-설명.md
```

- 예: `2026-10-12_spm-package-resolve-fail.md`, `2026-10-15_camera-permission-crash.md`
- 영어 소문자 + 하이픈. 날짜는 문제 발생일.

## 작성 규칙

1. `TEMPLATE.md`를 복사해서 해당 카테고리 폴더에 만든다.
2. **에러 메시지는 원문 그대로** 코드 블록에 붙인다 (검색용). 번역·요약 금지.
3. "원인"과 "해결"을 분리한다. 원인을 모르면 `원인: 미확인`이라고 쓴다.
4. 시도했지만 실패한 방법도 적는다 (같은 삽질 방지).
5. 관련 커밋, PR, 이슈, 참고 링크가 있으면 남긴다.
6. 작성 후 `INDEX.md`에 한 줄 추가:
   ```
   | 2026-10-12 | build | [SPM 패키지 resolve 실패](build/2026-10-12_spm-package-resolve-fail.md) | 해결 |
   ```

## 상태 값

| 상태 | 의미 |
|------|------|
| `해결` | 원인 파악 + 근본 해결 |
| `우회` | 동작은 하지만 임시 방편 (후속 작업 필요) |
| `미해결` | 아직 해결 못 함 |
